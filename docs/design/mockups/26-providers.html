What to look at

  • Add provider: the list is grouped by kind and searchable. Providers you've already added are greyed out, except Custom, which you can add more than once.
  • Pick one and the dialog asks only for what that provider needs: a key; a name, address, and key for Custom; or nothing for Ollama when it's already running.
  • Test and save works as it does today: Glossly only saves a key that works, and roles get filled in once the first provider connects.
  • Click a provider row to see Test again, Replace key, and Remove.
  • Click a model box under "Which model does what" for the searchable picker. Long names end in "…", and the provider name and arrow always stay visible. The list opens upward when there's no room below and scrolls inside itself, so the window edge never cuts it off.
  • No logos: each provider gets a letter tile, since the app has no accent colors (decision 39).

How it works underneath

The plan for building it, in the order I'd do it. Nothing here has been built yet. All of it runs on the AI SDK version we already use (ai 7). Each provider is one of four ways of talking to a model, plus its own address, key link, and model list.

1. Four ways of talking to a model

  • Chat Completions (createOpenAICompatible, already used for local servers): Groq, xAI, DeepSeek, Kimi, MiniMax, Mistral, Together, Fireworks, Baseten, OpenRouter, Vercel AI Gateway, Ollama, LM Studio.
  • OpenAI Responses (createOpenAI({ baseURL }), already used for OpenAI): OpenAI and Ramp Router. Ramp's docs say it has no Chat Completions endpoint, so it needs this one.
  • Anthropic Messages (createAnthropic({ baseURL })): Anthropic, and gateways that offer the Anthropic API (Ramp does too).
  • Google (@ai-sdk/google, a new package): Gemini.
  • So a preset is just data: a name, an address, a key link, and one of the four. Adding another gateway or host takes one entry, with no new code.

2. Presets, and the providers you've added

  • Presets (the list in the dialog): Groq, Gemini, OpenAI, Anthropic, xAI, DeepSeek, Kimi, MiniMax, Mistral, OpenRouter, Vercel AI Gateway, Ramp Router, Together, Fireworks, Baseten, Ollama, LM Studio, Other local server, Custom.
  • Connections (in settings): the ones you've added, like { id: 'openrouter', preset: 'openrouter' } or { id: 'custom-1', preset: 'custom', label: 'Work gateway', baseUrl, api: 'chat' }. Keys stay encrypted the way they are now, stored by connection id.
  • Model refs stay connection:model. Today's Groq, OpenAI, and Anthropic keys become connections with the same ids, so a migration moves the keys over and every saved role and override keeps working.
  • Custom asks for a name, an address, and an optional key. Test and save tries Chat Completions first, then Responses, and the result is shown, so you don't need to know which one a gateway speaks. You can still pick it yourself.

3. What changes in the model layer

  • createModel and listModels switch on the way of talking, not the provider name. Settings for reasoning effort and structured output (llm.ts lines 294 and 382 key them on 'groq' and 'openai') switch the same way.
  • Structured output already copes with models it doesn't know: a model missing from capabilities.json gets JSON mode with a retry, the same as a local model. Gateway ids like anthropic/claude-… drop the vendor/ prefix to find their known capabilities.
  • Ramp's model ids are specific to each account and come from its /v1/models, which we already call to test the key.

4. Picking models when there are hundreds

  • The model picker gets a search box and opens in whichever direction has room. Models that are in use or have known capabilities come first, and the rest appear when you type.
  • Automatic role picking only chooses models listed in capabilities.json, so a gateway key never puts an untested model on a role by surprise.
  • A short privacy line for gateways, hosts, and Custom: "Text goes to this service, and from there to the model's maker."

5. Model labels: what's known, what's listed, what's measured

  • Today every label (speed, cost, structured output, reasoning, and the hidden intelligence rank) comes from the hand-written capabilities.json. No benchmarks are fetched. That list stays the only source of the rank and of structured output, so it alone decides what Glossly picks for you.
  • Known through a gateway. Gateway ids drop their vendor/ prefix (and Ramp's provider: prefix) before the lookup, so openai/gpt-5-mini gets the same labels as gpt-5-mini.
  • Cost from the provider's own list. When the model list has prices (OpenRouter's does), a model with no entry still gets Low, Medium, or High cost from those prices. Thresholds are set per million tokens. A listed entry's cost wins over this.
  • Speed from your own calls. Each call already records how long it took (ms in the model layer). After about 10 calls, a model's label switches to its measured speed (output tokens per second plus time to first token, so short and long answers are judged fairly), shown with a dashed border. Measured speed replaces listed speed in the label and in auto-picking, since your connection is what counts. Nothing leaves the computer: it's worked out from the metrics table.
  • A model that is in no list stays Untested and is never picked for you, even when it has a price and a measured speed.

6. Choices for you

  • Which presets to include at launch. The mockup has 19, and trimming or adding them later is cheap.
  • Whether the setup's four big tiles should be Groq, Gemini, OpenAI, and Anthropic (as shown), or swap one for OpenRouter.
  • Can someone add the same preset twice (two OpenAI keys, say)? The mockup allows it only for Custom.
