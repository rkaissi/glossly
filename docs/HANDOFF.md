## Decisions made (deviations from the spec)

1. **AI SDK v7, not v6.** API notes: `instructions` replaces `system`; structured output is `generateText({ output: Output.object({ schema }) })` then `result.output`; full stream is `result.stream` (was `fullStream`), with `text-delta` parts carrying `.text` plus `error` and `abort` parts; ESM only; errors are `APICallError` (`statusCode`), `RetryError` (`lastError`), `NoObjectGeneratedError`, `StreamProviderError`. Docs ship in `node_modules/ai/docs/` (see `08-migration-guides/23-migration-guide-7-0.mdx`). Test mocks: `MockLanguageModelV4` from `ai/test` (constructor takes `doGenerate` / `doStream` results; result shape in `@ai-sdk/provider` `LanguageModelV4GenerateResult`: `content`, `finishReason: {unified, raw}`, `usage: {inputTokens:{total,...}, outputTokens:{total,...}}`, `warnings`).
2. **`node:sqlite` instead of `better-sqlite3`.** `new DatabaseSync(path, { allowExtension: true })` plus `db.loadExtension(require('sqlite-vec').getLoadablePath())`. Works in Vitest on Node 24 (tested) and inside Electron 44 (verified earlier). No native rebuilds. When packaging, sqlite-vec's DLL must be `asarUnpack`ed.
3. **No `uiohook-napi`.** It also installs a global keyboard hook, which breaks the privacy rule. The C# helper runs a mouse-only `WH_MOUSE_LL` hook and reports keyboard activity through `GetLastInputInfo` (it never sees which keys). The "mouse moved 200 px away" check is done in Electron by polling `screen.getCursorScreenPoint()` while the pill is visible.
4. **Evals use Vitest** (`pnpm eval`), not `cargo test`.
5. **Embeddings:** local `Xenova/all-MiniLM-L6-v2` (384 dims) through transformers.js in an Electron utility process, downloaded on first run into the app data dir, with a notice in first-run setup.
6. **Package manager:** pnpm. Rayan is more used to npm, so keep instructions simple.
7. **`DecisionProvider.decide(input, signal)`** takes `{ context, features, collections }` instead of the spec's `(input, questions)`; the questions are fixed by our output contract.
8. **Helper request arguments are top-level fields** next to `cmd` (e.g. `{"id":3,"cmd":"context","before":500,"after":500}`).
9. **Tier 2 on the hotkey path uses a focus hand-off.** The helper reads from the focused element, and on the hotkey path the overlay holds focus. So when an action is clicked, the shell calls `restore_focus` on the source window, reads `context_container`, then gives focus back to the overlay (helper `restore_focus` on the overlay's HWND, then `win.focus()`). This keeps the rule "tier 2 is read on action click" without reading it early. Blur-to-close is suppressed during the hand-off. Copy-fallback selections skip tier 2.
10. **"Delete all data" is a full reset (being changed, see Next steps, Step 12).** Currently the store's `deleteAll()` clears the `settings` and `models` tables, and `Services.deleteAll()` also removes every saved key and its last test result, reloads settings (back to defaults, `firstRunComplete` false), re-registers the default hotkey, and sends the settings window to `#setup`. Rayan decided on Oct 10 that Delete all data must keep keys and settings, with a separate "Reset settings" button for settings and keys.
11. **"Try it" captures from the settings window itself.** While the setup's Try-it step is mounted, the renderer sets `setup:try-it {active:true}`, and capture accepts the settings window's HWND as a source (`Capture`'s `captureSource` callback; every other Glossly window, the overlay included, stays ignored). The flag clears on unmount, window close, and any full reload. "Don't show here" is hidden for that window (it would otherwise set `electron.exe` to hotkey-only).
12. **Local only is strict (decided Oct 10, built in Step 12).** Nothing leaves the machine while it is on: the router uses rules, Save stores and embeds locally but skips entity extraction, and every model action (Ask now; Reply, Who, promises extraction, and Visualize's LLM fallback later) shows "Local only is on" with a way to turn it off. This goes beyond the spec, which only disables the router's call. Once local model support exists (Step 19), those calls go to the local model instead.
13. **Redesign (decided Oct 10, built in Step 13).** Frosted glass using real Windows 11 acrylic, light or dark following the system theme; monochrome, with no color accent; inspired by the ChatGPT and Codex apps. The bar fits its buttons, and a Glossly menu button sits at the left so that nothing ever moves when slots fill. Covers the overlay, the settings window, and setup.

### Step 4: Core tests, fixtures, router eval (complete)

111 unit tests pass. `src/router/router.test.ts` covers features, rules, slots, router fallbacks (timeout with abort, error, no_model, local_only), and `LlmStructuredDecision`. `src/llm/llm.test.ts` covers `AiSdkLlm` with `MockLanguageModelV4` (429 fallback before the first token, none after it, none on 401, `no_model`, native schema mode, the retry with the validation error, the Groq JSON-mode path, the decision role using Fast), plus `isFallbackError`, the catalog, roles, and `providers.listModels` with a fake fetch. - `fixtures/{messages,commitments,tables,articles,code,contacts}.json`: 60 cases, `{id, context: SelectionContext, expected: {content_type, slots}}`. `slots` is the ideal set for slots 3 and 4, order ignored.
- `evals/router.eval.ts` writes `evals/results/router-{rules,llm}.json`; `evals/print-results.mjs` prints the summary, the distinct error messages, and a table of misses. The LLM run needs `GROQ_API_KEY` (model `groq:qwen/qwen3.8-27b`, override with `GLOSSLY_EVAL_MODEL`) and reports errors and calls over 400 ms. It waits and retries on 429 (free-tier per-minute limit), so a full run takes about 3.5 minutes, and it fails if more than 10% of calls error (errored cases are scored on the rules fallback, which would otherwise hide a broken model call). Rayan asked to keep LLM eval runs rare because of the rate limits.
- The first rules run scored 78.3% type accuracy. These heuristics changed: code keywords count only on lines with code punctuation (plus Python block openers); articles need 35 or more words and 2 or more sentences (was 60 words); name pairs skip chat speaker headers and greeting words, and count 0.3 instead of 0.55 in articles, tables, and code; numeric tokens accept unit suffixes (42ms, 12.1k). Rules-only is now at **98.3% type accuracy and 90% slot match**. The tuning used the same fixtures it is scored on, so expect lower numbers on real selections; Rayan's real examples are the real test.
- Remaining misses: automated mail (shipping notice, all-staff notice, one-time passcode) gets Reply, because the spec scores Reply as `authored_by_other`, which is true for automated mail too. That is a scoring gap for Phase 2 Reply, not a rules bug. Also msg-16 (single first names, so no Who), msg-18 ("please" plus "today" reads as a commitment), and tbl-04 (a prose sentence with 26% numeric tokens, under the spec's 30% threshold).

### Step 5: LLM router eval (run Oct 9)

113 unit tests pass and core `tsc` is clean.

- **Groq retired the llama chat models.** On Oct 9 the key's model list has only these chat models: `qwen/qwen3.8-27b`, `openai/gpt-oss-20b`, `openai/gpt-oss-120b` (plus `allam-2-7b`, which is untested). The first run failed all 60 calls with "model does not exist". The stale llama entries in `capabilities.json` are harmless and still used by unit tests.
- **Reasoning models need a low effort.** `gpt-oss` spends about 500 reasoning tokens by default, which used up the router's 200-token cap and returned empty JSON (`json_validate_failed`). `capabilities.json` entries now take an optional `reasoning` (`none`, `minimal`, `low`); `AiSdkLlm.structured` sends it as `groq.reasoningEffort` (or `openai.reasoningEffort`). Qwen 3.8 uses `none`, gpt-oss uses `low`. gpt-oss is now marked `speed: medium` because reasoning adds latency.
- Single-call latency for the router: Qwen 3.8 (reasoning off, native schema) about 175 ms; gpt-oss-20b at low effort 320 to 550 ms; gpt-oss-120b at low effort 500 to 650 ms. Qwen with `structuredOutputs: false` failed schema validation, so it stays on `json_schema`.
- **Free-tier limits** (from the response headers) are the same for all three models: 1,000 requests per day and 8,000 tokens per minute, **per model**. A router call is about 470 tokens on Qwen, so about 15 router calls per minute per model. Model size doesn't change the limits, but spreading calls across models does: with only a Groq key, `updateRoles` picks Fast = Qwen 3.8 with fallback gpt-oss-20b, and Chat = gpt-oss-120b; a 429 moves to the fallback (a different model with its own limit). There's a unit test pinning these defaults.
- **Result** (`groq:qwen/qwen3.8-27b`, 60 cases, 0 errors): **100% type accuracy, 61.7% slot match**, median 247 ms, 3 calls over 400 ms. Rules-only: 98.3% type accuracy, 90% slot match. Almost every slot miss came from the model scoring `mentions_people` high when the only names were chat speaker headers (it added Who to 17 cases), plus a low `contains_commitment` on 6 commitment cases. `prompts/router-decision.md` now spells out what counts and what doesn't for both fields. **The tuned prompt has not been re-run** (rate limits); run `pnpm eval` once when convenient and record the slot number here.
- The router's 400 ms timeout means a slow call falls back to rules, so the LLM path's slot accuracy matters only when it beats rules. If the re-run stays below the rules' 90%, consider using the model only for `content_type` and `best_collection`, and computing people and commitment scores from rules.
